## Restart Policy

| Control | With saved choice | Without saved choice |
| --- | --- | --- |
| Master CAN output | Restore ON/OFF | OFF |
| Charge permission | Restore ON/OFF | ON, still subject to master and admission |
| Discharge permission | Restore ON/OFF | ON, still subject to master and admission |
| AutoCCL | Restore ON/OFF | ON |
| AutoCVL | Restore ON/OFF | ON |
| EOC timer | ON | ON |

EOC OFF is a supervised-session exception. No finishing counters or active
attempt are resumed across a restart. Fresh valid BMS data and existing
protection guards are still required before permission is advertised.
AutoCCL changes request immediate preference sync and log a failure if the
storage layer reports one; this is not a guarantee against power loss.

## Timer Display

The last validated timestamp can be a millisecond older than a newly started
timer. Previously their unsigned difference wrapped and was clamped to 600
seconds. The corrected diagnostic returns zero in that case and continues to
handle normal clock rollover. Charging decisions do not use this display value.
The qualified finishing interval, bounded discharge pause and BMS protections
are not shortened or bypassed.

## Reproduce

Use ESPHome 2026.9.1 and the pinned upstream package bootstrap. Keep credentials
in the ignored private files; never publish generated C++, binaries or NVS.
The two private files are `secrets.yaml` and `ota-password.yaml`, following the
existing deployment setup. Tests requiring ESPHome use that same Python
environment.

```bash
cd deployments/batteryops-mason
python bootstrap_packages.py
python tests/qualify_finish_session.py --output-dir /tmp/yam-regression
python tests/run_yambms_logic.py --finish-session --bounded-pause --output /tmp/yam-pause-core.json
python tests/run_yambms_logic.py --finish-session --bounded-pause --operating --output /tmp/yam-pause-parser.json
python tests/qualify_finish_diagnostics.py --output /tmp/yam-timer.json
python -m esphome compile yambms-reboot-timer.yaml
python tests/qualify_reboot_timer.py --compiled --output /tmp/yam-reboot.json
```

`tests/installed-reader-baseline.json` lets qualification verify the installed
reader's source hashes without relying on private evidence paths.
Restoration tests exercise ESPHome's actual restoration method with simulated
preferences. They do not prove physical flash persistence or mains-loss recovery.

## Supervised Installation

1. Confirm the operator is beside the system with mains available. Capture
   actual Yam switches, phase, fresh readings, GX limits and ESS/DESS settings.
2. Establish and verify the existing zero-current maintenance hold through
   native GX readings. Yam master OFF alone is not a guaranteed charger stop
   after GX cold boot. Do not infer effective discharge limit from an inverter
   setting alone.
3. Save master, charge and discharge stops before one OTA; retain NVS and the
   exact rollback image. Match the image digest to the private build manifest.
4. Verify new identity, saved stops, fresh data, zero admission limits and no
   active BMS faults under hold. Do not expose charge/discharge while checking
   restoration. EOC should be ON; AutoCCL/AutoCVL should match captured intent.
5. Restore the captured operating configuration only after admission checks
   pass, and verify native GX limits, current and control identity. DESS cloud
   planning and delivered-schedule checks are separate from firmware recovery.

An unattended power-loss test is not part of this release. A restart does not
prove future balancing completion, shunt synchronisation or overnight DESS
behaviour. No BMS thresholds, SmartShunt settings, tariff values or ABU wiring
are changed here.
